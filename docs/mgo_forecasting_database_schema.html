Clerk → application user → purchase plan

Clerk account ID user_abc123 → users.clerk_user_id → internal users.user_id UUID → purchase_plans.user_id

Clerk handles login. The backend verifies the login token and resolves this mapping before accessing a user's plan.

Current tables

A user can have many plans. Each market series contains zero or more observations. Each Procurement Officer has one Procurement Manager in an organisation; see PM and PO assignment.

Notes

  • There is no separate profile table. Display names can come from Clerk. Passwords are not stored here.
  • Every user has a unique, required Clerk ID. Email is optional because Clerk accounts may not have one.
  • Row Level Security is on for every table with no browser policies. Only the backend reads and writes these tables, and it enforces ownership itself.
  • Deleting a Clerk account removes memberships and PM assignments, and keeps the user row so plans and decisions stay on record.
  • A plan cannot be deleted while it has a recommendation response, decision, withdrawal or purchase record.
  • Unverified market unit and contract metadata stays nullable. Monetary series use USD by convention.
